# MP4 实施记录

功能在 codex/mp4-wallpapers 实现，已于 2026-10-21 合并到 main 并公开发布 v0.1.4。七项计划任务完成；独立全分支审查产生四项重要发现，已通过一次修复及回归验证，没有 Critical 或延期 Minor。

## 实施时作出的决定

以下按决策发生顺序记录，包括审查提出但未继续评估的边界。

1. 沿用现有功能分支和工作目录实施，保留 main。这样无需额外工作树；代价是同一目录中的并行修改需要协调。
2. 第五项任务先测播放器生命周期，真实桌面切换延后至第六项 IPC 接通后验收。集成问题会晚一项暴露，已在交付前完成实际验证。
3. 工厂接口增加可选的 signal、onError 上下文，用于取消加载和过滤过期错误。接口不匹配的风险由生命周期、renderer 与桌面检查覆盖。
4. 运行真实打包目录中的 EXE 与专用用户目录，替代执行 NSIS 覆盖现有安装，避免改变现有安装登记和快捷方式。因此安装器执行及实际 0.1.3→0.1.4 覆盖升级没有验收。
5. 用自有 Electron 场景适配器包裹冻结 V3 的编译后构造及 initialize 生命周期，及时取得资源所有者并取消初始化，同时保留 vendor 来源快照。它依赖当前实现的私有接口；未来更新 V3 时必须重新核对该接口并执行 renderer 与实际桌面检查。
6. 审查再次确认第四项的 NSIS 验收边界，没有把打包 EXE 运行写成实际安装器执行；实际升级仍需另行验证。
7. 设备范围保持已声明的 Windows 11 x64 和主显示器。其他设备、显示器和长期性能没有保证或验收。
8. 普通路径穿越、未登记媒体和受限目录清理有检查；没有额外建立抵御同权限外部进程恶意并发替换 junction / 符号链接的安全边界。同权限恶意文件篡改不在本轮保护或测试范围。
9. 官方资源支持作者命令生成的路径，没有增加对手工清单中 #、? 路径的兼容。正常命令不会生成这些路径；手工改写此类路径的作品可能播放失败并回退。

## 审查修复

- 当前代次加载失败后清除失败的 desired ID，使新设置快照可重试并上报有效错误；保留严格 ID / revision 校验。
- 初始化中切走场景时立即 destroy，取消其读取并释放 WebGL 上下文，不等待初始化结束。
- 文件丢失后的回退依据已登记作品类型，不再依赖媒体仍可读取。
- 作者导入使用同目录独占锁，明确拒绝并发读改写；正常失败释放锁并回滚本次目录。

具体测试、设备和证据路径见 [验收记录](verification.md)。
