# MP4 壁纸导入与官方壁纸随版本交付

日期：2026-10-15。用户已确定先支持 MP4，并要求我们作为作者新增的壁纸随软件更新交付。用户已在本会话确认本设计，进入实施计划阶段。

## 目标与使用者

普通用户把下载到电脑的 MP4 导入软件、选择为桌面壁纸，重启和升级后仍能使用。我们作为维护方导入准备好的 MP4，填写名称、作者等资料，随下一版软件交付；升级后的用户在官方壁纸列表中看到新增作品。

本阶段采用两种来源、同一个壁纸选择入口：官方壁纸随安装包交付，本地壁纸保存在当前用户的数据目录。界面使用“导入本地 MP4”，作者侧使用项目维护命令添加发布内容。“作者上传”在这一阶段指我们向项目的官方资源目录添加作品。

## 用户流程

设置窗口新增“壁纸库”页，默认展示该页。分为“官方壁纸”和“我的导入”，现有魈 / 璃月灯火作为官方实时场景继续显示。列表展示静态缩略图、名称、来源和当前选择；MP4 显示时长和分辨率。

点击“导入本地 MP4”打开 Windows 文件选择框，一次选择一个文件。软件复制到自己的用户目录，实际检查能否解码，生成静态缩略图后加入“我的导入”。导入成功即显示新卡片，由用户点击“应用到桌面”；取消选择或导入失败不会替换当前壁纸。重复操作期间按钮显示处理状态，不启动多个同时写入的导入任务。

用户可随时切回内置魈场景。只有“我的导入”提供移除操作，确认后仅删除软件保管的副本。移除当前播放项时先切回内置魈场景，再释放并删除视频文件；原始下载文件不受影响。

MP4 循环播放、默认静音。继续支持暂停 / 恢复、播放速度、显示时间日期、铺满屏幕 / 完整画面，新增视频音量。光影、昼夜、人物受光、粒子与采样画质仅在内置实时场景中显示，避免让用户误以为能改动视频里录好的内容。关闭设置窗口后桌面壁纸继续播放。

## 作者发布流程

作者入口采用维护命令，输入 MP4 路径、稳定作品 ID、名称和作者名称。导入过程复用视频检查与缩略图生成，输出到项目的官方视频目录，并原子更新官方视频清单。命令拒绝覆盖已有 ID；更新已有作品应明确修改相应资源和清单。

官方视频清单位于 content/official-videos/catalog.json，每项包含稳定 ID、名称、作者、相对视频路径、相对缩略图路径、时长、宽高和文件大小。资源按作品 ID 放在 content/official-videos/ 下。

prepare:web 合并原有实时场景与官方视频清单，将官方视频复制到 web/ 的独立目录。构建阶段校验重复 ID、清单结构和缺失文件；错误阻止生成候选安装包。原有 NSIS 与 GitHub 软件更新链路继续交付整个版本。

软件启动时读取当前安装版本的官方清单，并合并用户本地壁纸。新版本增加官方作品不会重新初始化用户设置，也不会覆盖用户导入的视频。列表按来源分区；新增官方作品显示在官方区，当前选择保持。首次实现若没有用户提供的正式 MP4，官方视频清单允许为空；验收视频单独放在 work/，不作为正式作者作品发布。

## 数据与兼容

本地视频和缩略图位于 %APPDATA%/GenshinEXE/wallpapers/local/ 下，每个作品使用软件生成的 ID 和独立目录。library.json 只记录本地条目；官方目录只读取安装资源。用户原文件名用于默认显示名称，不用于拼接存储路径。

SettingsStore 增加当前壁纸 ID 与视频音量。旧设置缺少这些字段时继续使用内置魈和静音。选择壁纸经过主进程验证，只接受当前合并目录中可用的 ID。恢复壁纸默认设置重置播放和画面控制，保留当前作品选择。

重启时当前作品不存在、媒体文件丢失或无效，则回退内置魈并给出明确提示。本地清单损坏时保留磁盘上的媒体文件，不阻止内置壁纸启动。软件更新删除或替换某个官方作品时同样验证选择。正常升级沿用稳定 appId 与原用户数据目录。

## 播放与资源访问

继续使用现有单个桌面 BrowserWindow 和 Progman / WorkerW 挂载。渲染适配层按选中类型创建现有 WallpaperRuntime 或 HTML video 播放器。切换前销毁原运行对象、定时器与事件监听，并释放媒体 / GPU 资源；切到视频后不保留内置 WebGL 场景在后台运行。

桌面播放器只接收作品 ID 与主进程生成的媒体 URL。原本仅绑定 127.0.0.1 的资源服务增加 MP4 MIME、HEAD 和单段 HTTP Range 响应，便于按需读取视频、循环和定位。官方文件来自 web/；本地媒体通过已注册条目的受限映射访问，不向网页暴露任意磁盘路径。

导入检查使用短时、隐藏的 Electron 媒体检查窗口：验证视频有画面、宽高和时长有效、能解码首帧，再生成缩略图。检查设置超时并在结束时销毁窗口；不向该窗口开放桌面控制或文件操作接口。文件选择、复制、登记和删除由主进程负责，只向设置窗口开放受限 IPC。

播放器上报当前作品 ID 和设置版本；主进程忽略旧作品 / 旧版本的迟到结果。设置同步、暂停和错误状态沿用现有机制。视频解码失败显示文件损坏或编码不受支持的提示；本阶段不自动转码，也不依据 .mp4 后缀承诺所有编码均可播放。

## 错误处理与保存

拒绝非 MP4、空文件、无视频轨道和无法解码的文件。复制、解码或缩略图生成失败时清理本次暂存副本，不登记半成品。清单与设置采用临时文件加原子替换，写入失败保留此前有效数据。清理只针对经过验证、位于预期作品目录内的软件副本。

作者导入失败不改动官方清单。运行期某个官方条目不可用时隔离该条目并记录原因，其他壁纸继续可用。导入进度与错误独立于当前桌面播放状态。

## 实现边界

- electron/library.cjs：本地条目存取、目录合并、注册和移除。
- electron/video-probe.cjs 及配套受限页面：实际解码检查与静态缩略图。
- electron/main.cjs、preload.cjs、settings.cjs：文件对话框、受限操作、选择验证和持久化。
- electron/asset-server.cjs：已登记媒体访问、MP4 类型和 Range。
- electron/wallpaper-renderer.mjs 与视频播放模块：按类型切换唯一运行对象。
- electron/settings/：壁纸库、静态卡片、来源标识和视频控制。
- scripts/：作者导入命令、官方目录构建与校验；README 与作者使用说明记录操作方法。

本阶段只导入 MP4，沿用 Windows x64 和主显示器支持范围。公开作者账号、线上投稿审核、云端文件存储、独立壁纸下载更新和其他引擎的场景包属于后续独立功能。

## 必要验收

保留现有 8 项检查，增加有实际边界价值的检查：本地清单跨启动保存与损坏恢复、无效导入不登记或替换当前作品、移除不影响原文件、官方增量目录合并不丢本地条目 / 当前选择、媒体路径限制与 Range 成功及错误响应。

使用专用验收 profile，实际验证正常 MP4 导入、缩略图、桌面动态播放、暂停 / 恢复、音量、两种显示比例、切回魈、重启恢复、损坏 MP4 拒绝和当前作品移除。检查旧运行对象已释放。作者导入一段验收视频，构建后验证它进入官方目录；模拟新目录增加作品，确认用户本地条目和选择保留。

完成网页构建与本地候选安装包验证，在安装版中确认 MP4 资源不依赖开发目录；记录实际检查结果和未覆盖的设备范围。正式发布继续使用已有 GitHub 发布流程。
