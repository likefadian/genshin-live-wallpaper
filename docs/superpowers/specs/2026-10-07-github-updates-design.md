# GitHub 软件更新 · 本地接入

用户已选定公开发布仓库 `https://github.com/likefadian/genshin-live-wallpaper`，并确认“开始接入，先完成本地验收”。沿用会话中已讨论的Electron + NSIS + electron-updater方案；公开上传和发布仍须在具体文件就绪后确认。

## 行为

软件设置页显示当前版本、发布来源和更新状态。用户点击检查，看到新版本与说明后自行点击下载；下载展示进度，校验成功后才允许“重启并安装”，点击后再次由原生对话框确认。普通退出不自动安装已下载更新。没有Release明确显示“尚无正式发布版本”，网络/下载/校验错误允许重试，不能假报最新版。

继续采用稳定appId、安装渠道、用户数据目录；原壁纸、画质、GPU选择及设置保持。更新操作只向设置窗口开放受限IPC。更新状态独立于渲染状态，更新失败不退出壁纸。发行说明作为纯文本展示。

## 实现边界

- `electron/update-controller.cjs`：检查、下载、状态转换、失败和再次检查；依赖注入electron-updater。
- `electron/update-source.cjs`：固定公开仓库配置；本地验收地址只允许显式 `--verify-update`、专用profile与127.0.0.1 HTTP服务同时存在，并按profile隔离下载缓存。
- 主进程负责确认安装、现有退出清理；设置页只触发受限操作，不接收可执行路径或任意更新URL。
- 默认不自动下载、不在退出时安装、不降级、不接受预发布渠道。正常启动不配置调试端口，不需要GitHub账号或发布凭据。
- 构建配置生成GitHub `app-update.yml`、`latest.yml`、NSIS EXE及blockmap；开发/打包继续显式 `--publish never`。
- 交付候选0.1.3。本地验收使用另行标记的0.1.3-verify.0安装版，通过真实electron-updater下载并安装正式0.1.3；测试包不公开发布。

## 必要验收

现有4项核心检查保留，新增更新状态和边界的少量核心检查。实际安装候选旧版，在专用用户配置中保留非默认设置，用本地HTTP更新服务检查/下载/校验/运行NSIS安装器到0.1.3，复核设置与动态桌面；一个损坏下载验证拒绝安装。真实GitHub源只读检查尚未发布状态。

本地链路通过不等于GitHub远程更新已验收。线上仍需要用户授权具体Release附件与正式发布，并进行真实远端旧版→新版升级。独立壁纸包、本轮代码签名、多机与长期性能不在本阶段。
